# Design

## What it is for

A person's professional history is elicited once, kept as facts, and compiled into as many targeted resumes as they need, by a coding agent, with every claim traceable to something they said. The alternative it replaces is the chat-window rewrite: paste a resume, get a rephrasing, lose the context when the window closes.

## Decisions

- **Interviews are the source of truth; resumes are derived.** A resume is a lossy, target-specific view. Keeping the facts separately means a new target never starts from an old resume's omissions, and a claim is elicited once. Alternative rejected: one evolving master resume as the only record, which is what most people have and why their resumes only ever shrink.
- **One folder per target.** `resumes/<target>/` holds the Markdown and the PDF for one job or job family, and `targets/<target>.md` holds what the job is and what happened. Versions are folders, not suffixes, so the status of each application sits beside the document that was sent. Alternative rejected: git history alone, which cannot show two targets side by side.
- **`resumes/base/` is the untargeted resume.** Every targeted resume is a reordering and rewrite of it, so the base carries the current best framing and the targets diverge from it rather than from each other.
- **`profile.md` holds decisions, not facts.** Facts belong to a role; framing decisions ("these roles stay separate", "never a founder listing") cut across all of them and are the thing a new session most often gets wrong. Writing them down the turn the user makes them, with their words, is cheaper than re-arguing them.
- **The interview is written, in rounds.** The agent appends a round of questions to the interview file, the user answers in their editor, the agent extracts facts and appends the next round. The file is the record, so nothing is transcribed later, and a round costs one read and one write instead of a conversation's worth of tokens. The user answers at their own pace, over days if they like. Alternatives rejected: a live chat interview, which costs tokens on every turn and produces a transcript that must then be cleaned into facts; a separate interviewer session, which worked but made the user carry files between two agents.
- **Interviewing and writing stay separate.** A round is written to serve the fact base, not one target, so the facts stay general enough for the next target.
- **Markdown master, scripted PDF.** The script renders a single-column, Helvetica, no-table, ligature-free document and verifies that every long word survives text extraction, because strict applicant-tracking parsers drop ligatures and tables. It auto-fits to two pages by trying spacing presets from roomiest to tightest; below the tightest preset the fix is trimming content, not type size. Alternative rejected: a word-processor template, which drifts from the content and cannot be regenerated by an agent.
- **User data is gitignored.** The public repository is the method; the history is the user's. A user who wants versioning forks privately and deletes the ignore lines, the same pattern as [tropestorm](https://github.com/megan-holstein/tropestorm).
- **Standard vocabulary is a rule, not a preference.** Postings and interview scorecards use the profession's names for practices; a resume written in private coinages is invisible to keyword screens and reads junior to a senior colleague. The agent corrects the user's language as it works.

## Evidence

The positioning rules rest on one published study of one employer (`docs/positioning.md`). The harness itself has no measured results yet. The measure that matters is response rate per target, which each `targets/<target>.md` records under **Status**; a user who keeps that log can see which framings worked.
